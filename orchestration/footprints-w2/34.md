**open_decisions:**
- Must additions be recorded in the same PR? Default: yes. The test fails on any id that is in the content but not in shipped.json, with the message 'run node tools/shipped.ts', and the generator only appends at the same version. Every push to main is deployed, so an unrecorded id is in players' saves with no guard. Sorted, one id per line and keyed by played map, the file keeps textual conflicts between parallel content PRs rare, and rerunning the generator resolves them.
- One file or per-area files? Default: one file, src/content/shipped.json, as the issue and EXPANSION §6 say.
- A snapshot per SAVE_VERSION, or only the latest with a `version` field? Default: latest only. The generator refuses to drop or move ids unless SAVE_VERSION > shipped.version and UPGRADES covers the gap. The test cannot catch a same-version hand edit, so leave that to review. Don't add a CI comparison against main's shipped.json, since it needs checks.yml changes that are #35/#37's.
- Must the check prove the upgrade maps each old id to its new one, or only that one is registered? Default: registered only, as the issue says, plus a convention that each upgrade comes with a fixture test in tools/tests/save.ts.
- Fix the two load bugs here or file them separately? First: groups added to a visited map never spawn (world.ts:103-106, :357). Second: a saved door on a frozen cell throws (world.ts:108). Default: fix both here and list them in the PR. The first is required anyway once the v1 upgrade is pure (tools/tests/save.ts:61), and #47 needs it. The second is a few lines.
- What goes in beyond the issue's list? Default: include map sizes (and the outdoors' 512x384), the OUTDOORS id 'caldera', zone sizes and conditions. Record only `used`-able ids (chests and once-events), not signs, rifts or repeatable events. Among flags, include content flags, guild_<hall> and 'donations'. Skip skill_swim/skill_mountaineer, which nothing sets. Skip saved key names (stat keys, the equipment slots weapon/armor/shield): they are code, the typecheck sees a rename, and it would need a bump anyway.
- Where the upgrade runs? Default: in deserialize (src/game/save.ts), with the registry in save.ts or a new src/game/upgrades.ts, so Game.loadGame (src/game/game.ts:77-91) needs no change.
- Where does guildFlag live? Default: src/game/party.ts, which src/ui/screens.ts:16 already imports and no other Wave 2 issue edits. Not src/game/map.ts, which #32/#33 may edit.
- Validate ids at load, so a renamed spell, class or item is refused rather than crashing later? Default: no. It is out of scope, and the shipped check stops such renames reaching main.
- Whether #34 edits docs/SLICE.md and CLAUDE.md. Default: SLICE.md :25-27, :275 and one Code map row only. No CLAUDE.md change: #37 owns that file in this wave, and the test's failure message tells a session what to run.
