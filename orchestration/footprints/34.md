**pitfalls:**
- Every future content PR touches shipped.json. If the test also demands that additions are recorded, it becomes a merge-conflict hotspot like the `interiors.length === 12` pin (tools/test.ts:95). Keep it one id per line, sorted, or per-area files, or fail only on removals/moves and add ids with the generator.
- 'Unless the change bumps SAVE_VERSION with an upgrade' can't be seen if shipped.json is regenerated in the same PR: once regenerated, the removed id is simply gone. Record the version in shipped.json and compare against it, or keep a snapshot per version, so the test can demand UPGRADES[v] for each version between the snapshot's and SAVE_VERSION.
- What a save actually holds (world.ts:25-49, party.ts:103-130): mapId and lastTown (played ids: harrow, caldera, mill, greywater1, greywater2, thornhold, grove1, grove2; 'caldera' is OUTDOORS, outdoors.ts:20, and not in MAP_DEFS); zones (zone ids shelf, thornmark); per map, `used` (chest and once-event ids), `groups` and truceGroups (encounter ids), `doors` ('x,y' of L/S squares, in PLAYED coordinates, so zone squares are offset by atlas `at`), and `explored` bits indexed y*width+x (world.ts:322/:341). Party: race, cls, spells, equipment (weapon/armor/shield item ids), pack and bag items, conditions, and flags. The issue's list leaves out map sizes (the width shifts every explored bit), the outdoors' size (ATLAS width 512 / height 384, atlas.ts:21-22), the OUTDOORS id, and saved key names such as `equipment.armor`.
- Flags set by code: the NPC `flag` values (q_ashcombe, q_greywater, q_grove); quest setFlag (q_*_done); guild_<name> (currently 'guild_Lantern Guildhall' from harrow.ts:38 and 'guild_Thornhold Lantern Hall' from thornhold.ts:41); `donations` (screens.ts:333). skill_swim and skill_mountaineer are read (party.ts:283-284) but set by nothing yet.
- STALE/imprecise: 'rename a spell and the save no longer loads'. The load succeeds. spell() (spells.ts:67-71) throws later, on the character sheet (screens.ts:229), the cast menu (:247, :291) or in combat (combat.ts:46). A renamed MAP does stop loading: ensureMapState throws (world.ts:100), and loadGame (game.ts:84) doesn't catch it. A renamed class or race, or an equipped armor/shield, crashes the first frame: frame.ts:180 reads CLASSES[c.cls].name, and party.ts:183 reads ITEMS[id].ac.
- STALE: 'rename a guardian and it lives again' is only true on a map the save never visited. On a visited map the renamed group never appears at all. Real bug, verified: ensureMapState seeds groups only when a map's state is first created (world.ts:101-104), and liveGroups skips any def without state (world.ts:349-354). So a group ADDED to a visited map never spawns in an old save. That breaks 'new content only adds' for every new outdoor zone (#47): the 'caldera' state exists in every save, so none of a new zone's groups would ever appear. The fix is small: seed missing group ids in ensureMapState.
- Moving a door or zone can CRASH the load, not just misplace a door. world.ts:107 assigns `.door` onto `m.at(x, y)`. When the saved square is out of bounds or void, that is the frozen OUT_OF_BOUNDS (map.ts:293) or VOID_CELL (map.ts:196), and it throws 'Cannot assign to read only property' (verified for harrow '40,40' and caldera '5,5'). Guard it or drop such doors.
- The v1 upgrade must freeze v1 geometry: harrow, mill, greywater1, greywater2, thornhold, grove1 and grove2 were 16x16; shelf and thornmark were 32x32 (the same as today). No map file changed since v2 was introduced in 7366b55. Only src/content/atlas.ts changed (+17/-1). Detect v1 by data.version, never by array length (world.ts:136), and fold zone state with the frozen 32 width, not z.w (:148).
- The version isn't passed into World today. Tests (tools/test.ts:752-756 pre-weather, :757-785 v1) construct World straight from a state object. Move the upgrade to a pure function in save.ts or world.ts taking (data, maps), and route Game.loadGame and the tests through it.
- JSON: tsconfig.json has no resolveJsonModule, and Node 22 needs `with { type: 'json' }`. Read shipped.json with node:fs in tools (as tools/harness.ts:23 does) and keep it out of the game bundle.
- The outdoors' `used` and `groups` are shared across zones (layOutdoors enforces unique ids, outdoors.ts:90-99). Other maps keep them per map. Key shipped ids by played map.
- Upgrades must be pure data transforms. They must not read current content geometry except through the frozen tables, or a later map change silently alters old upgrades.
